# WebDAV 同步

WebDAV 是源时提供的**私有云同步与备份**能力：**同步文件先加密再上传**，服务端永远只看到密文。你可以使用自建的 WebDAV 服务器，数据完全由自己掌控。

## 设计要点

- 云端文件名形如 `sourcetime-20261014-154512.enc`，**每次推送生成一份带时间的快照，不覆盖历史**。
- 服务端只保存 AES-256-GCM 加密后的密文文件，无法解密。
- 同步文件**不包含 WebDAV 配置**，WebDAV 配置与 TOTP 数据分离存储。
- 传输默认强制 `https`，明文 `http` 需用户在设置中显式开启。

## 配置 WebDAV

在「WebDAV」页面填写服务器信息：

| 字段 | 说明 |
|---|---|
| 服务器地址 | 你的 WebDAV 根地址（推荐 `https://`） |
| 用户名 | WebDAV 账号 |
| 密码 | WebDAV 密码（本地按安全方式存储，不写入同步文件） |
| 同步目录 | 存储加密备份的目录，不存在时自动逐级创建 |

配置完成后可使用「测试连接」验证可用性。

::: warning 安全提示
WebDAV 密码与 TOTP 数据分离保存，且 WebDAV 密码不会进入同步文件。请使用专用的、权限受限的 WebDAV 账号。
:::

## 手动同步

- **Push（上传）**：将本地加密数据库推送为一枚带时间戳的加密快照。
- **Pull（下载）**：从云端拉取最新的加密快照并解密合并到本地。

## 自动同步策略

- **自动 Push**：新增 / 删除验证码后自动推送（可关闭）。
- **自动 Pull**：应用启动时自动拉取（可关闭）。
- 自动同步失败不会回滚本地操作，本地数据永远保持第一优先级。

## 并发与冲突

- **同步队列**：Push / Pull 通过队列串行执行，避免并发竞争。
- **冲突策略（V1）**：Last Write Wins（以最后写入为准）。
- **Revision 规则**：以修订号判断新旧，避免误覆盖。

## 同步文件结构

```text
sourcetime-YYYYMMDD-HHMMSS.enc
└── AES-256-GCM 密文（内含加密后的数据库快照）
```

## 同步失败与重试

- 自动同步失败时有明确的状态反馈，不阻断本地使用。
- 支持手动重试；网络恢复后可再次 Push / Pull。

## HTTP 状态处理

| 状态 | 处理 |
|---|---|
| 2xx | 成功 |
| 401 / 403 | 认证失败，提示检查账号或权限 |
| 404 | 目录不存在时尝试自动创建 |
| 其他 | 记录日志并提示用户 |
