# 安全设计

源时把「数据本源、用户掌控」放在第一位。本页说明加密方案、安全边界与强制安全要求。

## 三条安全原则

1. **本地为本**：原始凭据只存在用户本机，云端仅存加密副本；本地数据永远是第一优先级，同步失败绝不回滚本地操作。
2. **自主可控**：同步服务器由用户自己搭建、自己管理。
3. **全程密文**：备份、传输、存储全程加密，无裸数据暴露。

## 加密方案

```text
用户输入字符串 / 系统安全随机数（256-bit）
        ↓
PBKDF2-HMAC-SHA256（随机 16 Bytes Salt）
        ↓
AES-256-GCM（随机 IV，校验 Authentication Tag）
        ↓
加密单文件 totp.db.enc
```

- **KDF**：PBKDF2-HMAC-SHA256，配合随机 16 Bytes Salt 派生密钥。
- **加密**：AES-256-GCM，使用随机 IV，并强制校验 Authentication Tag 保证完整性。
- **随机密钥**：256-bit 系统安全随机数。
- **本地格式**：加密 JSON 单文件 `totp.db.enc`。

## 密钥保管

- 应用**不内置固定主密钥**，密钥由用户手动输入或一键随机生成（256-bit）。
- 密钥保管采用 **Asset Store Kit（DEVICE_UNLOCKED 档）**，并可叠加**可选 PIN 应用锁**。
- 源时**不会保存明文加密密钥**，也不提供服务器端找回功能。

::: danger 请务必妥善备份密钥
若忘记或丢失加密密钥，已加密数据可能无法恢复。密钥是解密本地数据与云端备份的唯一凭据。
:::

## 强制安全要求

**必须：**

- 使用系统安全随机数、随机 Salt、随机 Nonce / IV。
- 必须验证 Authentication Tag。
- 传输默认强制 `https`。

**禁止：**

- 禁止 ECB、无认证的 CBC 等不安全模式。
- 禁止自行设计密码学算法。
- 禁止内置默认加密密钥。
- 禁止明文写入文件 / Preferences / 日志。
- 禁止明文上传 WebDAV。

## 敏感数据处理

- **TOTP Secret 内存处理**：敏感字段只在必要作用域内存留，用后及时清理。
- **日志脱敏**：密钥、口令等敏感字段在落盘前统一脱敏，运行日志仅供本机诊断。
- **数据库内存策略**：解密后数据不长期驻留，按需加载、使用即释放。

## PIN 应用锁

- 设定后进入后台自动上锁，回到前台需解锁才能查看口令。
- 与系统安全能力结合，降低设备被他人临时接触时的泄露风险。

## 隐私政策

首次启动弹出隐私政策，同意后方可进入；政策版本重大升级时会重新要求确认。应用无统计、无埋点、无第三方云端上传。
