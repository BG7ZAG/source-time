## 编译报错：AddTotpSheet 括号层级错（已修）
报错 `Declaration or statement expected` / `'}' expected` / `Cannot find name 'build'` / `struct must have ... one build`：用 python 批量重建 `manualCard()` 时少了一层收尾 —— `if (this.showAdvanced) { ... }` 的 `}` 之后，还需要再一个 `}` 才能关掉外层「高级选项 Column」，导致 `.width()` 成为游离语句、方法体未闭合、`build()` 被当成语句。

可用 `/tmp/balance.py <file...>`（剥离字符串/注释后统计括号深度，final depth 必须为 0）快速体检。

   **★ 真正原因（截图确认）**：**ArkUI 的 `Scroll` 在子内容高度不足一屏时会把子组件垂直居中**，所以列表看着像浮在页面中间。`align` 其实定义在 `CommonMethod<T>` 上（common.d.ts:20310/20355），**所有组件包括 Scroll 都能用**（我先前的 grep 只查了 scroll.d.ts，误判为不可用）。官方/社区解法二选一：给 Scroll 加 `.align(Alignment.TopStart)`（**推荐，内容超屏时也不影响滚动**），或给子容器 `height('100%')`（内容超屏会失去滚动）。
   本轮做法：6 个带 Scroll 的页面（Settings/About/PrivacyPolicy/Scan/Security/WebDav）统一加 `.align(Alignment.TopStart)`；Scroll 直接子容器再加 `.constraintSize({ minHeight: '100%' })` + `.justifyContent(FlexAlign.Start)` 双保险（minHeight 不影响超屏滚动，height 100% 会）。**新写 Scroll 页面时记得默认带上 `.align(Alignment.TopStart)`**。

## WebDAV 输入框输入后被清空（已修）
**根因两个数叠加**：
1. `TextInput({ text: value })` 只做单向传值。官方文档明确写「建议通过 onChange 将状态变量与文本实时绑定，**避免组件刷新时 TextInput 中的文本内容异常**」—— 页面一旦重渲染，输入框文本会被重置回传入的 prop。
2. WebDavPage 有个 **页面级 `@State pulseOn` + 1400ms `setInterval`**，每 1.4s 触发一次整页重渲染 → 刚输入的内容被回滚/清空。
**修法**：
- 新增 `WebDavField` 子组件（`@Link value` + `TextInput({ text: $$this.value })` **$$ 双向绑定**，API 10+，官方支持 @State/@Link/@Prop/@Provide），父组件用 `WebDavField({ value: $baseUrl, ... })`（@Link 用 `$变量名` 传引用）。四个字段全部替换，删掉原 `glassField` @Builder 与 `focusedField` 状态。
- 新增 `PulseDot` 子组件，把脉冲状态与定时器收进组件内部（`@Prop @Watch('onActiveChange') active`），页面不再周期性重渲染。
**同类隐患（未改）**：SecurityPage、AddTotpSheet 仍是 `text: value` + onChange 的单向写法，目前没有周期性刷新所以没暴露；若后续给这些页面加计时器/轮询，必须一并改成 `$$` 绑定。

## WebDAV "测试链接" 误报"路径不存在"（已修）
**根因**：`WebDavService.testConnection` 只对目标目录发一次 `PROPFIND(Depth:0)`，新配置下同步目录（默认 `/SourceTime/`）在服务器上还不存在 → 服务器返回 404 → `statusMessage(404)='远程路径不存在'`。深层问题：整条同步链路都假设目录已存在 —— `SyncService.pushInternal` 直接 `upload(PUT 文件)`，首次同步也会因目录不存在而 409/404 失败。
**修法（全在 `service/WebDavService.ets`）**：
- 新增幂等 `createDirectory(config)`（`customMethod:'MKCOL'`）：201/2xx 成功；**405（集合已存在）视为可用**；401/403 走 `WEBDAV_AUTH_FAILED`；其余 `WEBDAV_CONNECTION_FAILED`。
- `testConnection`：PROPFIND 返回 **404 → `await createDirectory` 再验证**（仍失败才透传错误），消除"路径不存在"误报；目录会被客户端建好。
- `upload`：PUT 前 `await createDirectory`（幂等），根治首次推送失败。
- `download`：GET 返回 **404 → `WEBDAV_INVALID_REMOTE_FILE` + '远端暂无备份数据'**（而非"路径不存在"），拉取未推送过的账号时提示更准。
教训：WebDAV 同步目录本应由客户端建立，测试/上传前都应 `MKCOL` 兜底；`statusMessage` 的 404 文案只在"真路径错误"场景使用，目录创建类流程要单独分流。
静态校验：括号平衡 0；`createDirectory` 定义 1 处、`await this.createDirectory` 2 处。仍无法本地 hvigor 编译，需在 DevEco 构建验证。
