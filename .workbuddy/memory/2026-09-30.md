# 2026-09-30 源时（source-time）主页 TOTP 排查

## 背景
用户报「主页中 totp 计算不对」，排查分支 `develop`（当前 HEAD 407312c）。

## 排查结论
1. 算法层（TotpService / Base32Utils / TimeUtils）**已验证正确**：
   - 把 `base32Decode` + `counterToBytes` + `truncate` 原样搬到 Node 跑 RFC 6238 全部向量（SHA1×6、SHA256、SHA512、6 位补零）→ 全过。
   - `base32Decode` 与参考实现（bit-string 累加器）逐长度 1..45 对比 → 0 差异（去 padding 也能正确解码）。
   - HMAC 调用方式（`createMac(alg)` + `createSymKeyGenerator('HMAC')` + `convertKeySync` + `initSync/updateSync/doFinalSync`）与华为官方 HMAC 文档一致；`'HMAC'` 规格支持密钥 [1,4096] 字节。
   - 计数器为 8 字节大端，`offset = last & 0x0F`、`& 0x7F` 掩码、`% 10^digits` 均正确；时间戳单位统一为秒。
   ⇒ 数值本身不会错，问题不在 TotpService。

2. **真正的缺陷（commit 407312c 引入）**：主页验证码生成从 HomeViewModel 的「统一 Timer 每秒重算」挪到了 `TotpCard` 自己的 `setInterval`，且**只在倒计时回卷（remaining 1→30）时才重算**：
   - 判据 `newRemaining > this.remaining` 只能捕捉「tick 间隔 < 1 个周期」的窗口切换。切后台/锁屏/UI 卡顿导致 tick 间隔 ≥ 1 个周期时，窗口切换会被漏掉 → 卡片继续显示**上一个（已过期）时间窗**的验证码，最长整整一个周期（30s）。概率约 50%（旧值/新值都是 1..30 均匀分布）。
   - 旧实现（单 Timer → `refreshTime()` + `refreshItems()` → 每个 item 无条件重算）永不 stale，所以这是本次 UI commit 引入的回归。
   - 违反 spec §43「不要每个卡片创建一个独立 Timer」、§77「Timer 不创建大量对象」；也违反 README「页面不直接访问 TOTP 核心算法」（卡片直接 new TotpService 并生成）。

## 修复方向
判据从「剩余秒数回卷」改为「时间窗序号变化」：`Math.floor(nowMs/1000/period)`（tick 延迟任意长都能正确切换），并把生成收回 ViewModel/统一 Timer（spec §43）。

## 附带发现（未修）
- 重启后 `AppStorage` 里的 `encryptionSecret` 丢失，且没有解锁页（EntryAbility 在 encryptionInitialized=true 时直接进 HomePage）→ 主页空列表，只能靠 SecurityPage 改密钥流程绕。
- `HomePage.aboutToAppear` 的 `loadData()` 与 `onPageShow()` 会并发触发两次 `viewModel.load()`。

## 真正根因（用户给了具体 URI 后定位）
用户案例：`otpauth://totp/QCS:bg7zag%40gmail.com?secret=…&issuer=QCS&algorithm=SHA512&digits=6&period=30`，App 结果与 Vaultwarden 不一致。

先用仓库代码原样跑 RFC 6238 全量向量（SHA1/SHA256/SHA512 × 6 个时间点 × 8 位/6 位，6 位按 RFC 4226 截断取 8 位末 6 位）→ **36/36 全过**，证明 `TotpService`/`Base32Utils` 对 SHA512 + 6 位也是正确的（包括 RFC 的 64 字节 SHA512 密钥）。

根因在 `AddTotpPage.ets` 的 `onSecretChange`：
- 把 otpauth 链接粘进"密钥"输入框 → `onChange(链接)` → 解析成功，设置 `secret/algorithm=SHA512/…`，`parsedFromUri=true`，return。
- 输入框是受控的 `TextInput({ text: this.secret })`，框架把回填后的新文本又抛回一次 `onChange(base32)`（ArkUI 官方行为："代码修改绑定变量也会触发 onChange"）。
- 第二次进入非链接分支 → `if (this.parsedFromUri)` 成立 → **把 algorithm 重置成 'SHA1'**、issuer/account 清空，然后保存 → DB 里存的是 SHA1 → 主页按 SHA1 算 → 与 Vaultwarden(SHA512) 不一致。
- 即"算法计算不对"实际是"算法被静默改成 SHA1"。扫码录入路径（ScanPage.applyParsed）没有输入框，不受影响。

修复（`AddTotpPage.ets`，+8 行）：
- 非链接分支开头加 guard：`if (value === this.secret) { return; }`（吞掉受控 text 回填的 echo，也顺带消掉每次按键的重复回调）。
- 解析出非默认 algorithm/digits/period 时自动展开高级选项（`this.showAdvanced = true`），让被解析出的算法可见。

注意：**已存在的条目 algorithm 已经以 SHA1 存进加密 DB，必须删除后重新添加**（App 没有编辑功能）。

后续可选（未做）：`TotpService.hmac` 用的是通用 `'HMAC'` 规格；华为文档规定"密钥长度等于摘要输出长度时用 `HMAC|SHAxxx`"。若重新添加后仍不一致，再考虑按该规则切换 SymKey 规格。

## 第三个问题：点保存报「数据加载失败」（缺解锁流程，spec §80）
根因：spec §80 明确要求「启动应用 → 输入加密密钥 → 解密数据库 → 进入首页」，但实现漏了这一步——`EntryAbility` 见到 `encryptionInitialized=true` 就直接进 HomePage；而加密密钥只存在 `AppStorage`（**进程内内存，重启即丢**，代码里没有 PersistentStorage）。
于是任何一次进程重启（DevEco 重新 Run、应用被杀）后：密钥丢失 → 主页空列表 → 进 Add 页保存时 `AddTotpViewModel.encryptionSecret === ''` → `repository.load('')` 解密失败 → 报 `数据加载失败`（`StorageService.initialize()` 全项目从未被调用，所以 `getDatabase()` 也是 null）。

修复（4 个文件）：
- `SecurityPage.ets`：新增解锁模式 —— `@State locked`（= 已初始化但 AppStorage 无密钥）、`@State unlockSecret`、`onUnlock()`（有本地加密文件就解密校验，校验通过才 `AppStorage.setOrCreate` + `replaceUrl(HomePage)`；无文件时任意非空密钥即可）、`unlockView()` builder；`header()` 在 locked 时隐藏返回键、标题改「解锁数据」；`build()` 分支加 `else if (this.locked)`。
  注意：从「设置 → 安全」进入时 AppStorage 有密钥 → `locked=false` → 仍是原来的改密钥流程。
- `EntryAbility.ets`：`privacyPolicyAccepted && (!encryptionInitialized || !unlocked)` → 加载 SecurityPage（冷启动直接进解锁页）。已确认 `AppStorage` 在 UIAbility 里可裸用（华为官方示例就在 onWindowStageCreate 里 `AppStorage.setOrCreate`，无需 import）。
- `HomePage.ets`：新增 `hasEncryptionSecret()`；`aboutToAppear`/`onPageShow` 在无密钥时 `replaceUrl(SecurityPage)`；隐私弹窗同意后的分支也带上该判断。
- `AddTotpViewModel.ets`：保存前若 `encryptionSecret` 为空 → 返回 `KEY_REQUIRED` + 「尚未解锁，请返回首页输入加密密钥」（替代误导性的「数据加载失败」）。

仍未做：spec §81 的「后台超时自动锁定」V2 项；`StorageService.initialize()` 是死代码。

## 更正 + 最终方案：关键资产存储托管密钥（用户否定了"启动要输入密钥"）
用户明确「加密针对的是本地存储和 webdav，进应用不需要解密」⇒ 上一节做的「启动解锁页」方向错了，已用 `git checkout --` 回退 4 个文件（SecurityPage / HomePage / EntryAbility / AddTotpViewModel，回退前用 `git diff` 确认过这些文件里只有我的改动）。

用户选择「系统密钥库」方案，改为用 **Asset Store Kit（`@kit.AssetStoreKit`）** 保管密钥：
- 新增 `entry/src/main/ets/service/KeyStoreService.ets`：`save/load/remove`，alias=`sourcetime_encryption_secret_v1`，`SECRET`+`ALIAS` 必选、`ACCESSIBILITY=DEVICE_FIRST_UNLOCKED`、`DATA_LABEL_NORMAL_1` 标签；save 走「先 remove 再 add」避免别名冲突（NOT_FOUND=24000002）；load 用 `RETURN_TYPE=ReturnType.ALL` 取回明文；所有失败都降级为返回 ''/false，不抛给 UI。
  API 约束（华为官方文档）：SECRET 1–1024 字节必选、ALIAS 1–256 字节必选、IS_PERSISTENT=true 才需要 ohos.permission.STORE_PERSISTENT_DATA（未设置，卸载即清除）。
- `EntryAbility.ets`：`onWindowStageCreate` 先 `keyStoreService.load()`，拿到密钥就 `AppStorage.setOrCreate('encryptionSecret', secret)`，再抽出的 `loadContent(windowStage, secret)` 里做原来的路由 → **启动静默自动解锁，不再要求输入密钥**。
- `SecurityPage.ets`：首次设置 / 修改密钥时，除了 AppStorage 与 Preferences，额外 `keyStoreService.save(...)`，失败只 toast 提示不阻塞。
- `AddTotpViewModel.ets`：密钥为空时返回 `KEY_REQUIRED` + 指向「设置 > 安全」的可操作提示，替代原来误导性的「数据加载失败」。

注意（已告知用户）：
1. Asset Store Kit 是系统能力，**DevEco Previewer 可能不支持**，密钥读写会降级失败 → 需真机/模拟器验证。
2. 文档 `SourceTime_AI_Coding_Implementation_Spec_v1.0.md` §79（禁止缓存密钥）/§80（启动必须输入密钥）与本次实现冲突，待用户决定是否改文档。
3. 遗留：`HomeViewModel.load()` 失败（密钥不对/文件损坏）时主页只是空白，没有错误提示；`SyncService.autoPullOnStart()` 从未被调用（README 的"启动自动 Pull"未接线）。
